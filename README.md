# Инна — студия. Сайт-портфолио с формой брифа

Одностраничный сайт иллюстратора: иллюстрации, сториборды, вертикальные и горизонтальные сериалы, аватары. Главная цель посетителя — заполнить бриф; бриф уходит владельцу в Telegram и/или на email.

Без сборки и без npm-зависимостей: чистый HTML/CSS/JS + Node.js (18+) для бэкенда.

## Структура

```
public/            сайт (раздаётся как есть)
  index.html       разметка
  styles.css       стили, токены, мобильный адаптив, prefers-reduced-motion
  main.js          рендер контента из data.js + отправка формы (loading / error / sent)
  data.js          ВЕСЬ КОНТЕНТ: работы, отзывы, цены, контакты, флаг showPrices
  img/             сюда кладём картинки и видео
api/brief.js       serverless-функция для Vercel: POST /api/brief
lib/brief.js       общая логика: валидация, антиспам, уведомления (Telegram, Resend)
server.js          локальный сервер / вариант для VPS (статика + /api/brief)
test/brief.test.js тесты обработчика (npm test)
.env.example       переменные окружения
design_handoff_inna_portfolio/  исходный дизайн-референс и ТЗ (не используется в проде)
```

## Запуск локально

```bash
node server.js
```
Откройте http://localhost:3000. Без настроенных уведомлений форма работает в «dev-режиме»: бриф печатается в консоль сервера, на сайте показывается «Спасибо».

## Уведомления о брифе

Скопируйте `.env.example` в `.env` и заполните **хотя бы один** канал.

**Telegram (рекомендуется)**
1. В Telegram напишите `@BotFather` → `/newbot`, скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, найдите `"chat":{"id":123456789}` и запишите число в `TELEGRAM_CHAT_ID`.

**Email через Resend**
1. Зарегистрируйтесь на resend.com, создайте API-ключ → `RESEND_API_KEY`.
2. `BRIEF_TO_EMAIL` — куда присылать брифы (можно несколько через запятую).
3. Пока свой домен не подтверждён в Resend, отправитель остаётся `onboarding@resend.dev` (письма приходят только на адрес аккаунта Resend). После подтверждения домена укажите `BRIEF_FROM_EMAIL=Бриф <brief@ваш-домен>`.

Если каналов нет, в production `/api/brief` отвечает 503 и посетитель видит ошибку с прямыми контактами.

## Деплой на Vercel

1. Импортируйте репозиторий на vercel.com (Framework Preset: **Other**, ничего менять не нужно — `vercel.json` уже указывает папку `public`).
2. В Settings → Environment Variables добавьте переменные из `.env.example`.
3. Deploy. Форма будет слать запросы на `/api/brief` того же домена.

## Деплой на VPS

```bash
git clone <repo> && cd inna
cp .env.example .env && nano .env
PORT=3000 node server.js          # или через pm2: pm2 start server.js --name inna
```
Перед сервером поставьте nginx/Caddy с HTTPS и проксированием на порт 3000.

## Как заменить контент и картинки

Всё в `public/data.js`. Картинки кладите в `public/img/` и указывайте путь в `src`:

```js
{ title: '«Сад у реки»', src: 'img/sad-u-reki.jpg' }
{ title: 'эп. 1', src: 'img/ep1.mp4', video: true, poster: 'img/ep1.jpg' }   // видео: muted autoplay loop
```
Пока `src` пустой — показывается плейсхолдер. Раздел «Цены» выключается флагом `showPrices: false`.

Рекомендуемые размеры: иллюстрации 4:5 (800×1000), сториборды и горизонтальные серии 16:9 (1280×720), вертикальные серии 9:16 (720×1280), аватары 1:1 (600×600), портрет 3:4.

## API

`POST /api/brief` — JSON `{ name, contact, type, about, budget }`.
Ответы: `200 {ok:true}`, `400` (валидация), `429` (больше 5 запросов за 10 минут с одного IP), `502` (все каналы уведомлений не сработали), `503` (каналы не настроены).
Скрытое поле `website` — ловушка для ботов: если заполнено, запрос тихо игнорируется.
